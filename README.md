# Make The One 계산·검색 구현 초안

이 폴더는 Master PRD v0.3의 한국 가상 원국 정책을 실행 가능한 코드로 옮긴 초안이다. 계산·검색 코드와 출처를 확인한 이름 자료를 포함한다. 로컬 Meta 호출과 PostgreSQL 16 연결을 검증했다. `/me`는 이름 느낌·가상 출생연도 범위와 독립된 이름/사주 세 쌍을 지원한다. 1980-2039년 4개 도시 색인을 생성했으며 전체 20개 도시와 공유 기능의 완료 여부는 별도다.

## `/me` 화면

2026-11-03 읽기 쉬운 사주 풀이: `전체적인 성향`, `일과 재능`, `돈을 대하는 방식`, `인간관계와 연애`의 네 항목으로 나누어 강점과 어려워할 점, 생활 속 모습을 쉬운 말로 설명한다. 전문용어와 계산된 구성은 기본적으로 닫힌 `풀이의 계산 근거 보기`에 둔다. 네 기둥만으로 일간 오행과 십성군 분포·합충을 살펴 직접 작성한 창작 풀이를 조합하며, 같은 비중의 주요 십성군은 모두 반영한다. 한자 독음과 같은 원국에는 같은 풀이가 나온다는 원칙을 유지한다. 이름 선정 이유와 이야기 연결은 포함하지 않는다. `interpretation`은 `kind: chart`, `sections`, `basis`, `references`를 반환한다. API의 `evidence`는 기존 검색 근거로 구분한다. 풀이 문장은 미리 작성해 두고 사주 조건에 따라 선택·조합한다. 요청마다 새 문장을 만들거나 무작위로 표현을 바꾸지 않으며, 같은 원국·문구 버전에는 같은 풀이가 나온다. 문체는 “~하는 성향입니다”처럼 직접 끝맺는다. 추가 모델 호출·추천 점수식·이름 태그 변경은 없다. 자미두수의 생활 영역별 구성은 참고했지만 별도 명반 계산을 도입한 것은 아니다. 시기별 대운 풀이는 원본 PRD의 별도 설계안이며 미구현이다.

변경 전 구현은 체크포인트 `62de56a`로 커밋했다. 이후 읽기 쉬운 풀이 변경은 별도 커밋으로 묶는다. 단위 테스트 56개·타입 검사·프로덕션 빌드가 통과했다. 이후 문장 종결 방식만 수정하고 관련 풀이 테스트 6개를 통과했다. 이 문구 수정에는 전체 빌드·보안 검사를 반복하지 않았다. 다섯 십성군별 풀이·동률 반영·180개 간지 조합의 근거와 응답 범위를 검증했다. 실제 합성 API는 약 5.60초에 HTTP 200과 네 항목·계산 근거 5개를 반환하고 프론트 응답 검증을 통과했다. 풀이·응답 검증·화면 렌더링 세 경로의 Codex Security 검사에서 보고된 발견·보류·미확인 질문은 0건이다. 전체 앱의 배포 검증을 뜻하지 않는다. 새 형식과 맞지 않는 이전 결과는 이야기를 유지한 입력 상태로 복구한다. 브라우저 시각 검증과 사람에 의한 풀이 품질 검수, 기존 호출량·지출 제한의 배포 검증은 남아 있다.

2026-11-03 생성 지연 수정: 병목은 모델 응답 대기였다. 동일 합성 서사의 비교 측정에서 기본 설정은 모델 18.15초(DB 0.89초, 이름 선정 0.02초), `reasoning_effort: minimal` 적용 시 모델 3.43초(DB 0.79초, 이름 선정 0.03초)였다. 추론 토큰은 2,154개에서 221개로 줄었다. [공식 추론 설정](https://dev.meta.ai/docs/reasoning)에 따라 최소 추론과 [출력 한도](https://dev.meta.ai/docs/protocols/chat-completions) `max_completion_tokens: 2048`을 명시했고, 모델·원문 근거 검증·재시도·20/40초 제한은 유지했다. 실제 앱의 107자·1200자 합성 입력은 모두 HTTP 200과 유효한 이름 3개를 반환했다(전체 5.27초·4.80초). 이 소수 표본은 15초 P95나 모든 입력의 품질·성공을 입증하지 않는다.

서버의 `model attempt timing`은 시도별 헤더 대기·본문 수신·전체 시간, 성공/오류 코드와 숫자 토큰 수만 남긴다. `generation timing`은 입력·모델·DB·이름 선정 시간을 구분한다. 원문·모델 답변 본문·자격증명은 시간 로그에 넣지 않는다. 단위 테스트 47개가 통과했고 테스트 훅 타입 수정 후 관련 모델 검사 11개와 프로덕션 빌드·타입 검사를 재검증했다.

결과는 서로 다른 원국과 이름을 하나씩 연결한 세 카드다. 각 카드에 이름·검증된 한자 또는 순우리말 표시·뜻·가상 생년월일시·도시·연주/월주/일주/시주를 보여준다. 원국과 이름의 중복을 거부하며, 사주 풀이는 카드별 펼쳐보기에 둔다. 출생 시각에는 DB에 저장된 UTC 오프셋을 붙인다. 응답 검증은 각 카드의 네 기둥·오프셋·이름 종류·한자/순우리말 의미 필드와 세 쌍의 유일성을 확인하고 이전의 공유 사주 응답을 거부한다.

선호하는 이름 느낌은 `상관없음 / 남성적인 느낌 / 여성적인 느낌`이며 실제 성별이나 사주 계산에 적용하지 않는다. 중성적인 이름은 양쪽 후보에 포함한다. 가상 출생연도는 지정 안 함, 1980년대부터 2030년대까지의 프리셋, 양끝 포함 직접 범위 입력(1980-2039년)을 지원한다. 연도 조건은 현지 양력 출생 날짜에 먼저 적용하고 해당 범위 안에서 대표 발생을 고른다. 이야기 모티프는 한 번 추출하며 사주 상위 30개의 이름 조합에서 중복 없는 세 쌍의 점수 합을 최대화한다(`three-pairs-v1`, 쌍별 `0.8C+0.2N`). 세 쌍이 부족하면 422와 조건 조정 안내를 반환한다. 이름 느낌·한자/순우리말 분류와 단어 뜻은 버전 관리하는 이름 원본에서, DB와 검증된 내용이 일치하는 행에만 결합한다. 이름 자료 변경 후 `npm run load:names`를 실행한다. 기존 v1 행의 뜻·한자 등이 같을 때만 버전을 v2로 전환한다.

순우리말 이름 `하늘`, `이슬`은 국립국어원 한국어기초사전에서 확인한 단어 뜻과 프로젝트의 창작 이름 풀이를 분리한다. 한자를 만들어 붙이지 않으며 한자 이름과 같은 후보군에서 평가한다. 종류별 결과 수를 강제하지 않는다. 한자 확인·단어 뜻 출처 링크는 결과 화면에 표시하지 않는다. 이름 느낌과 자연스러움은 초기 편집 판단이며 사람 검수·사용 빈도 통계가 아니다. 대운·시기별 풀이는 후속 과제이고 이름 느낌과 계산용 방향/가정은 별도로 설계한다.

2026-11-02 대표 결과 변경: 네 기둥의 누락·개수·형식 회귀 검사를 포함해 단위 테스트 40개와 타입 검사·빌드가 통과했다. API와 사주 계산·추천 순위는 이번 변경에서 수정하지 않았다. 모바일·데스크톱의 시각적 결과 확인은 별도로 남아 있다.

한국어 이야기 30~1200자를 입력하면 `/api/generate`의 `recommendations`에 담긴 독립된 가상 출생과 이름 세 쌍을 보여준다. 재미 이름은 추천·API 응답에서 제외했다. 찾는 동안 입력 대신 화면을 채운 Canvas 2D 밤하늘에서 별이 은은하게 반짝인다. 결과가 도착하면 그중 별 하나가 떨어지고, 낙하가 끝난 뒤 이름을 공개하고 프레임 루프를 멈춘다. 움직임 줄이기 설정에서는 정적인 밤하늘과 결과를 바로 보여준다. `새로운 이름 찾기`는 입력 상태로 돌아가며 적어둔 이야기와 이름 느낌·연도 선택은 컴포넌트 메모리에 유지한다. 같은 이야기를 다시 요청할 수 있지만 다른 결과를 보장하지 않는다. 브라우저 저장이나 원문 서버 저장은 추가하지 않았다. 색상과 치수는 [디자인 기준](DESIGN.md) 및 `app/styles/design-tokens.ts`를 따른다. 정적 스타일은 vanilla-extract로 생성하며 외부 이미지·웹폰트·애니메이션 렌더링 라이브러리를 사용하지 않는다. 실제 생성에는 서버 Meta 키와 PostgreSQL 색인·이름 적재가 필요하다. `/character`, PNG 카드, X 공유와 분석 이벤트는 후속 범위다.

2026-11-02 리뷰 수정: 가상 출생의 현지 일시는 DB에서 문자열로 반환해 서버 시간대에 따른 변환을 막는다. `/me` 생성 요청은 응답 본문 수신까지 제한 시간을 적용하고 시간 초과 시 입력과 재시도를 복구한다. 현재 화면 대기 제한은 아래 모델 지연 수정에 따라 60초다. DB 연결 대기는 5초로 제한한다. 당시 응답 지연·재시도·API 오류 회귀 검사를 포함한 단위 테스트 21개, 타입 검사와 빌드가 통과했다. 기존 PostgreSQL 16.15 컨테이너를 재시작한 뒤 `TZ=Asia/Seoul npm run test:db`의 현지 일시 보존·반복 적재·변조 거부·롤백 검사 4개도 통과했다.

2026-11-02 연결 확인: 기존 작은 색인과 이름 데이터로 실제 Meta·DB 생성 API의 HTTP 200 및 이름 3+1개 반환을 확인했다(합성 서사 한 건, 약 21.6초). 별도 합성 서사 한 건은 후보 부족으로 422를 반환했다. 이 결과는 모든 입력의 생성 성공이나 성능 목표 충족을 의미하지 않는다. 브라우저에서 생성·유성·결과 표시를 함께 확인하는 절차는 별도로 남아 있다.

2026-11-02 화면 흐름 변경 후: 재미 이름 없는 실제 API 응답(이름 3개, 합성 서사 한 건, 약 11.6초), `/me` HTTP 200, 단위 테스트 31개, 타입 검사와 빌드가 통과했다. 테스트는 낙하 완료 후 결과 공개, 이야기 유지 후 재요청, 오류 복귀, Canvas 프레임 정리와 움직임 줄이기를 포함한다. 브라우저의 시각적 동작은 추가 확인이 필요하다. API 호출량·동시성·지출 제한은 기존 미구현 항목으로 남아 있으며 공개 배포 전 해결해야 한다.

2026-11-02 탐색 효과·모델 지연 수정: 별의 밝기·크기 변화와 푸른 광채를 강화했다. 실제 서버 로그의 약 24초 HTTP 503은 Meta 요청 두 번이 각각 12초에 중단된 오류였다. 모델 요청은 본문 수신을 포함해 회당 최대 20초, 재시도와 대체 모델을 합쳐 총 40초로 제한하며 화면은 60초까지 기다린다. 오류 응답은 모델 시간 초과(504), 모델 응답 검증 실패(502), 모델·DB 연결 실패(503)를 구분한다. 로그에는 단계·안전한 오류 코드·업스트림 HTTP 상태만 남긴다. 단위 테스트 39개·타입 검사·빌드가 통과했고 실제 합성 서사 API가 약 10.3초에 이름 3개를 반환했다. 이 단일 실행은 15초 P95 목표나 모든 입력의 성공을 입증하지 않는다.

2026-11-02 후속 리뷰 수정: 모델 응답 본문의 수신 실패는 서비스 연결 오류(503), 수신 완료 후 JSON·모티프 검증 실패는 응답 검증 오류(502)로 분리했다. `fictionalBirth.utcOffsetMinutes`로 DB의 역사적 오프셋을 전달하고, 현지 시각과 함께 표시한다. 단위 테스트 45개·타입 검사·빌드와 실제 DB 검사 4개가 통과했다. 회귀 검사는 본문 연결 중단·재시도·안전한 로그, 1988년 중복 시각의 오프셋별 구분, 필수 오프셋의 응답 검증과 실제 DB 직렬화를 포함한다.

동일 수정의 실제 합성 서사 API는 약 17.7초에 HTTP 200과 `utcOffsetMinutes: 540`을 반환했고 프론트 응답 검증 및 `UTC+09:00` 포맷을 통과했다. 변경 경로 보안 검사는 보고된 발견 0건이며, 기존 호출량·지출 제한 및 배포·브라우저 시각 확인 게이트는 남아 있다.

2026-11-04 이름 느낌·연도 범위·독립 결과 검증: 단위·회귀 검사 64개, 실제 PostgreSQL 검사 6개(연대/직접 범위·대표 발생 선택·후보 상한 전 핵심 근거·적재 멱등성·변조 거부·롤백), 최종 프로덕션 빌드·타입 검사가 통과했다. 1980-2039년 4개 도시 색인은 파일 해시 검증 후 기존 데이터를 보존하며 원자 적재했다. 실제 합성 API는 1980년대·남성적, 1990년대·여성적, 1985-1995년·상관없음에서 각각 약 10.95/6.73/6.34초에 HTTP 200과 서로 다른 세 사주/이름을 반환했고 프론트 검증·연도 범위·이름 느낌 확인을 통과했다. 직접 범위 사례에는 순우리말 이슬도 포함됐다. 비활성 근거뿐인 핵심 모티프는 기존 보호 정책대로 422를 반환한다. `/me` HTTP 200과 입력 HTML은 확인했다. 9개 변경 경로 Codex Security는 기존 익명 모델 호출의 총 호출량/지출 제한 부재 한 건(low)을 보고했다. 이후 작은 매개변수 기반 핵심 근거 필터 변경은 수동 검토·DB 회귀·빌드로 확인했다. 브라우저 시각·상호작용과 사람 품질 검수, 기존 공개 배포 보호 장치는 미완료다. 대운은 후속 백로그로 남겼으며 커밋·push·배포는 수행하지 않았다.

## 브랜치 운영

`main`은 배포 가능한 코드, `develop`은 개발 통합, `feature/<작업명>`은 기능·수정·문서 작업을 담당한다. 최초 `develop`은 최신 `main`에서 만들고, 이후 작업은 최신 `develop`에서 분기하여 `feature/*` → PR → `develop` → 배포 PR → `main` 순서로 합친다. 프론트엔드·백엔드 상시 브랜치는 두지 않는다. 검사와 승인 등 상세 절차는 [Git 작업 가이드](docs/guides/GUIDE_GIT.md)을 따른다.

공개 전 `python3 scripts/check_publish.py`로 stage된 파일 전체를 검사한다. CI는 커밋 트리를 검사한다. 내부 PRD 연결은 로컬로 준비한다. 상세 경계와 한계는 [공개 전 검사 가이드](docs/guides/GUIDE_PUBLISH.md)를 따른다.

### 개발 환경·데이터 검증 (2026-11-01)

- Node 24.22.2 공식 체크섬 확인, typecheck·단위 테스트 18개·프로덕션 빌드 통과. 앱 lockfile 111개 패키지 OSV 조회에서 보고된 취약점 0건. 전체 보안 감사나 향후 안전성 보증은 아니다.
- Meta 1.3 Standard에 합성 서사를 보내 구조화 추출과 근거 검증 성공. 원문 개인 서사를 사용하지 않았다. 키·DB 접속 정보는 Git 제외 로컬 환경 파일에만 둔다.
- KASI 공식 1920-2100 배포 자료 중 1980-2039의 1,440개 절기를 대조했다. 양쪽을 분 단위로 반올림한 차이의 최댓값은 1분, 원시 오차 최댓값은 71.829초다. 1분 초과 시 색인 생성을 중단한다. 실제 절기 경계는 반올림하지 않는다.
- 2024년 서울·성남·속초·목포 작은 색인: 원국 4,406개, 발생 17,620개, 모티프 근거 162,575개. PostgreSQL 16.15에 이름 84개와 함께 적재했다. 반복 적재, 파일 변조 거부, 실패 시 트랜잭션 롤백을 실제 DB에서 검증했다.
- 진지한 이름 72개와 별도 창작 별명 12개를 준비했다. 한자·독음·기초 뜻의 출처와 프로젝트의 창작적 조합 뜻을 구분한다. 자연스러움 점수는 초기 편집 평가이며 사람 패널의 검수 완료를 의미하지 않는다. [데이터 출처와 검증 범위](data/README.md)를 따른다.
- 생성 파일의 해시와 적재 검증은 계산 정책의 출시 승인을 의미하지 않는다. 정책 상태는 `draft`다. 브라우저 실기능·전체 추천 흐름·배포는 아직 확인하지 않았다.
- Next.js `agentRules: false`로 AGENTS.md 자동 확장을 막는다. sandbox에서 파일 단위 통과만 표시하는 테스트 결과는 유효한 근거로 쓰지 않고 승인된 환경에서 실제 테스트 수를 확인했다.

## 순서

1. `db/001_init.sql`: PostgreSQL 16에서 정책, 절기, 도시, 네 기둥, 발생, 서사 근거, 이름, 빌드 이력을 분리한다. 같은 정책과 네 기둥은 하나의 `chart_id`로 중복 제거한다.
2. `tests/calendar.test.ts`: KASI 2024 입춘, 성남 경도, 23시, 속초·목포, 1988 서머타임, 2000 무오 기준을 검사한다.
3. `scripts/build-index.ts`: 절입과 평균태양시 두 시간 구간을 나누어 원국·발생·서사 근거 JSONL을 gzip으로 만든다. `manifest.json`에 건수와 체크섬이 남는다.
4. `scripts/load-index.ts`: PostgreSQL에 정책→도시·절기→원국→발생→근거를 적재한다.
5. `app/api/generate/route.ts`: Meta Model API로 원문에서 소재를 추출하고, DB의 검증된 원국·이름만 추천한다.

## 실행

```bash
nvm install
nvm use
npm ci
npm run typecheck
npm test
npm run build
```

Node는 [공식 24.22.2 LTS](https://nodejs.org/en/blog/release/v24.22.2)를 사용한다. `.nvmrc`는 버전 선택 파일이며 새 셸에서 자동 전환을 보장하지 않으므로 `nvm use` 후 `node --version`을 확인한다. 전역 nvm 기본 별칭은 변경하지 않는다. CI도 `.nvmrc`를 읽는다. Node 변경 시 `.nvmrc`, package.json의 engines, lockfile의 루트 engines 및 검증 기록을 함께 갱신한다.

Meta·DB 연결에는 `.env.example`을 참고해 `.env`에 서버 환경 변수를 준비한다. `POSTGRES_PASSWORD`는 충분히 긴 무작위 값을 사용하고 `DATABASE_URL`에도 동일한 비밀번호를 URL 인코딩해 넣는다. 예시 값을 실제 자격증명으로 사용하지 않는다. 아래 DB 명령은 `.env`, 이어서 `.env.local`을 읽으며 이미 설정된 셸 환경 변수가 우선한다.

```bash
docker compose up -d
npm run db:init
npm run check:services -- --db
# 합성 서사로 실제 Meta 호출 (API 사용량 발생)
npm run check:services -- --meta
npm run build:index -- 2024 2024 seoul,seongnam,sokcho,mokpo data/generated/pilot-2024
npm run load:names
npm run load:index -- data/generated/pilot-2024
npm run test:db
# 실제 연대 선택을 지원할 60년 색인 (출처 확인된 4개 도시)
npm run build:index -- 1980 2039 seoul,seongnam,sokcho,mokpo data/generated/years-1980-2039
npm run load:index -- data/generated/years-1980-2039
```

DB는 `127.0.0.1:5432`로만 공개하며 named volume에 보관한다. 초기화 명령은 기존 완성 스키마를 보존하고 연도 검색 인덱스만 멱등 추가한다. 일부 테이블만 있는 경우 중단한다. 색인 생성은 비어 있지 않은 출력 폴더를 덮어쓰지 않는다. `test:db`는 로컬 개발 DB를 대상으로 하며 이름과 색인을 먼저 적재한다. 기존 색인과 함께 검증할 수 있으며, `INDEX_DIR`로 검사할 색인 폴더를 지정할 수 있다.

`npm run build:index -- 1980 2039 all data/generated/full`은 전체 20개 도시를 대상으로 한다. 대규모 적재 전에 용량·DB 비용과 모든 좌표의 출처를 확인한다. 현재 GeoNames 덤프와 대전의 기존 좌표가 일치하지 않아 전체 생성은 보류한다. 임의로 좌표를 바꾸지 않았다. 실시간 API는 `MODEL_API_KEY`와 검수된 이름 자료가 없으면 503을 반환한다.

## 테스트 범위

`npm test`는 절기·시간 보정 경계와 추천 규칙을 검사하고, `npm run typecheck`와 `npm run build`는 형식 및 Next.js 빌드를 확인한다. GitHub Actions에서도 커밋과 PR마다 같은 검사를 실행한다. 실제 DB 적재 회귀 검사는 `npm run test:db`로 분리하며 CI의 PostgreSQL 16 서비스에서도 실행한다. `/me`의 실제 생성과 시각적 동작은 Meta·DB가 준비된 브라우저에서 추가 확인이 필요하다.

계산 정책: 평균태양시 = UTC + 경도×4분, 연·월은 UTC 절기 순간, 일은 태양시 23시, 시간은 2시간 단위. 절입은 astronomy-engine 2.1.19, 역사적 법정시는 moment-timezone 0.6.5의 전체 시간대 자료를 사용한다. `data/ruleset.json`은 명리 해석 규칙표 v1의 48개 매핑을 옮긴 것이며 일부 12운성 규칙은 검색에서 제외되어 있다. 숫자 점수는 서사 추천용 편집 규칙이다.
