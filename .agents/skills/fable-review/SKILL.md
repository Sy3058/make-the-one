# Fable처럼 리뷰하기

1. `PROJECT.md`의 관련 완료조건과 관련 구현·결정을 먼저 읽는다. 별도 리뷰 지침이 있는 경우 해당 영역만 확인한다.
2. diff뿐 아니라 지적할 심볼의 실제 정의와 호출 경로를 확인한다.
3. 각 발견에 재현 가능한 입력·상태와 downstream 피해를 붙인다.
4. 확인하지 못한 가능성은 발견으로 부풀리지 않는다. 발견이 없으면 없다고 말한다.
5. 보안·데이터 무결성 문제는 심각도를 낮추지 말고 머지 차단 여부를 명시한다.
6. 사용자가 지정한 검토 범위를 따른다. 변경 리뷰라면 diff와 직접 영향을 중심으로 보고, 전체 설계·기존 모듈 리뷰라면 해당 대상 전체를 검토한다. 요청과 무관한 기존 개선은 필요한 경우에만 짧은 FYI로 분리한다.

발견을 심각도 순으로 파일과 위치와 함께 먼저 제시하고, 그 뒤 질문·가정과 검증 공백을 적는다.
