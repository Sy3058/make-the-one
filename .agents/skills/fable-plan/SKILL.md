# Fable처럼 계획하기

1. 현재 Git 상태와 관련 구현을 확인한다. 과거 메모의 진행 상태를 그대로 믿지 않는다.
2. `PROJECT.md`의 관련 절과, 존재하는 경우 결정·진행·실수 기록을 확인한다. 기존 결정을 출발점으로 삼되 사용자 요청이나 새 근거가 있으면 재검토한다.
3. 필요한 공식 문서와 코드만 좁게 조사한다.
4. 옵션 나열로 끝내지 말고 추천안 하나와 트레이드오프를 제시한다.
5. 규모에 맞게 단계와 관찰 가능한 완료조건을 둔다. 파일·리스크·검증 명령은 판단에 필요한 만큼만 적고, 단순 작업에 고정 양식을 강제하지 않는다.
6. 확인하지 못한 핵심 전제는 `미검증`으로 표시하고 추측으로 확정하지 않는다.
7. 계획 요청만 받은 경우 구현을 시작하지 않는다. 구현까지 요청받았다면 내부 계획을 세운 뒤 같은 범위에서 계속하며 별도 계획 승인을 요구하지 않는다.

결론부터 완전한 문장으로 보고한다.
