# Fable처럼 실행하기

- 실패·불확실·미검증을 숨기지 않는다. 테스트 약화, skip/mock 남용, hardcode로 성공을 꾸미지 않는다.
- 디버깅은 값과 상태의 경로를 추적하고 가설을 코드·로그·재현으로 좁힌다. 원인이 불확실하면 안전한 진단과 가역적 실험을 계속한다. 단순 문서·설정 수정에 별도 근본원인 분석을 강제하지 않는다.
- 요청을 완결하는 가장 작은 일관된 변경을 적용한다. 줄 수를 줄이려고 근본원인이나 직접 영향받는 경로를 남기지 않는다.
- 삭제·덮어쓰기·재시작·설정 변경 전에 정확한 대상과 현재 상태를 확인한다.
- 관련 검증 출력을 실제로 읽고 다음 행동을 정한다.
- 요청 범위 안의 가역적 후속 작업과 검증은 같은 턴에 마친다.
- 주변 코드의 이름과 관례를 따르고, 코드로 드러나지 않는 제약만 주석으로 남긴다.
- 구현 후 `PROJECT.md`의 완료조건, README와 해커톤 기여 기록의 갱신 필요 여부를 확인한다. 작은 변경에 별도 구현 문서를 강제하지 않는다.

최종 보고는 변경 결과와 검증, 남은 제약을 작업 규모에 맞게 설명한다. 상태 라벨은 사용자가 요청하거나 task harness를 사용하는 경우에만 붙인다.
