# Jev 개발 하네스 시험 운영

2026-10-28 사용자 요청으로 실제 TypeSafe API를 호출했다. 제품의 Meta 모델은 변경하지 않았고, 개발 작업을 보조하는 별도 도구다.

## 현재 운영 방식

- 현재 메인 모델 Sol Medium을 유지한다. Jev는 작업 배정·파일 관련성·완료 근거·추가 승인 필요성에 대한 추천만 반환한다.
- 범위가 명확한 짧은 검색마다 호출하지 않는다. 배정이 애매한 작업이나 후보 파일이 많은 조사에서 작은 상태를 만들어 참고한다.
- 판단 결과가 원래 작업 지침과 충돌하거나 불확실하면 메인이 원래 근거로 판단한다. 어떤 결과도 모델 실행·파일 제외·명령 실행·승인 권한을 자동 부여하지 않는다.
- 실제 작업에서 사용한 사례와 불일치를 별도 기록해 보고, 대표성이 있는 작업이 쌓인 뒤 자동화 여부를 판단한다. 합성 사례의 일치율을 제품 개발 성공률로 설명하지 않는다.

## 실행

표준 Python 3.10 이상만 필요하다. 추가 패키지는 설치하지 않는다. 인증은 `TYPESAFE_API_KEY` 환경변수 또는 명시적으로 지정한 `--env-file`에서 읽으며, 이 저장소에 키를 복사하지 않는다.

```bash
python3 scripts/jev_harness.py \
  --task '새 입력 폼과 검증·로딩·오류 상태를 구현하고 단위 테스트를 추가한다.' \
  --output experiments/jev/task-unique-id.json
```

같은 출력 파일이 있으면 덮어쓰거나 다시 과금하지 않고 중단한다. 네트워크 재시도는 자동 수행하지 않으며 요청 timeout은 20초다.

묶음 평가는 `--task` 대신 `--cases experiments/jev/routing-v1.json`을 사용한다. `--reverse-options`는 Choice 선택지 순서만 뒤집고, `--dry-run`은 외부 호출 없이 실제 전송 payload만 표시한다. `--env-file`은 필요한 경우 실행자가 로컬 파일을 명시한다. 사례 JSON에 적힌 상태만 전송하며 저장소·대화·소스 파일을 자동 수집하지 않는다.

사례 형식은 `id`, `kind`(`route`, `relevance`, `completion`, `risk`), `state`, 선택적인 `expected`다. 기대값은 평가에만 쓰고 API로 전송하지 않는다. 입력한 상태와 실제 질문·응답·토큰 사용량·호출 지연은 출력 파일에 남으므로 상태에 자격증명이나 사적인 대화는 넣지 않는다. 기록을 Git에 추가하기 전 내용도 확인한다.

## 첫 실제 호출 결과

모델 `jev-1.14.0`, 질문 버전 `sol-harness-v1`로 고정했다. 기대값은 첫 호출 전에 메인 에이전트가 작성했다. 답을 본 뒤 질문·라벨·임계값을 바꾸지 않았다. Choice는 원래 선택을 기록하고, Noul은 0.7 이상 yes / 0.3 이하 no / 나머지 uncertain으로 기록했다. 이 임계값은 이번 시험의 시작값이며 보정된 기준이 아니다.

| 시험 | 기대값 일치 | 비고 |
| --- | --- | --- |
| 이번 실행기 개발 작업의 배정·파일 선택 | 4/6 | 배정은 Sol Medium. 새 테스트는 uncertain, 지침 문서는 불필요로 판단 |
| Sol 중심 작업 배정 | 17/20 | 한국어·영어, 계획·구현·디버깅, 단순 보안 키워드, 불명확한 요청 포함 |
| 파일 관련성 | 8/8 | 전부 합성 파일 설명. 실제 코드 검색 recall 측정 아님 |
| 완료 근거·추가 승인 판단 | 11/12 | 계획만 작성한 작업의 완료 판정은 uncertain |
| 같은 배정 사례에서 선택지 순서 뒤집기 | 16/20 | 20개 중 1개 결과 변경; 새로운 독립 사례가 아님 |

성공한 호출은 5번, 개별 판단은 중복 포함 66개다. 입력은 총 18,307토큰, 출력은 3,143토큰으로 보고됐다. 요청별 지연은 182.00-250.05ms, 중앙값 214.25ms다. 묶음 요청 지연이며 개별 판단당 지연으로 나누지 않는다. 초기 sandbox DNS 실패는 이 성공 호출 집계에 포함하지 않았다.

[공식 단가](https://docs.typesafe.ai/models)의 입력 $0.042/백만 토큰, 출력 무료를 적용하면 총 추정 모델 요금은 **$0.000768894**다. 실제 청구서·호스트 비용·전체 Codex 작업 비용을 측정한 값은 아니다.

원본 사례, 요청과 응답 기록, 집계는 `experiments/jev/`에 보존했다. 요청의 `expected` 미포함 여부·응답 계약·실제 모델 버전·사용량과 배정의 선택지 순서를 확인할 수 있다. `summary-v1.json`은 첫 5회 호출의 고정 집계다.

## 실제로 드러난 한계

- 원인이 아직 확인되지 않은 일반 디버깅을 Sol Low로 낮췄다. 메인 라벨은 Sol Medium이었다. 첫 응답 confidence는 0.46이었다.
- 알고리즘이 주어진 작은 구현을 Luna Low로 배정했다. 메인 라벨은 Sol Low였다. 이 응답의 confidence는 0.77이므로 단순 confidence 기준만으로 불일치를 모두 걸러낼 수 없다.
- 무관한 지침이 섞인 검색 요청은 Astra로 속지는 않았지만 `clarify`로 우회했다. 원래의 한정된 검색을 이어가는 동작과는 다르다.
- 실제 작업의 새 테스트 파일에 대한 Noul은 0.65였다. 임계값을 낮춰 맞춘 것처럼 보고하지 않고 불확실한 결과로 유지했다. 메인이 테스트 필요성을 판단해 작성했다.
- 완료 근거 판정은 작업 유형에 영향을 받았다. 코드가 아닌 계획 작성 완료 사례에서 0.52가 나왔다.
- 파일 관련성의 합성 예제 성적은 좋았지만 현재 작업의 문서·테스트 선택과는 결과가 달랐다. 실제 파일을 자동으로 버리는 기능에는 연결하지 않았다.

현재 판단은 **추천 도구로 사용을 시작할 수 있을 만큼 작동했고, 자동 실행·필터링을 맡길 증거는 아직 부족하다**다. 비교용 Sol API 호출, 작업 해결률·총 시간·재작업량 비교는 수행하지 않았으므로 전체 개발 비용이나 속도가 개선됐다고 주장하지 않는다.

## 검증과 다음 관찰

오프라인 검사는 `python3 -B -m unittest discover -s tests -p test_jev_harness.py -v`로 실행한다. 가짜 키와 가짜 응답만 사용하며 실제 provider를 호출하지 않는다.

후속 실제 작업에서는 추천 경로·최종 담당·결과·되읽기·지연을 함께 남긴다. 파일 관련성은 원문을 보존한 상태에서 누락 사례를 확인하고, 완료 판정은 실제 검사 출력과 요청 범위를 함께 제공한다. 기존 권한과 Git 승인 절차는 유지한다.

## 실제 완료 근거 확인 추가 호출

첫 5회 평가 이후 이번 작업의 실제 구현·9개 테스트 통과·호출 기록·한계 보고를 요약하여 완료 근거를 확인했다. Jev Noul은 0.4로 uncertain이었다. 긍정 응답을 얻으려고 재질문하거나 임계값을 바꾸지 않았다. 메인은 실제 증거와 요청 범위를 대조하여 완료 여부를 판단한다.

이 후속 호출까지 합하면 실제 성공 호출 6회, 판단 67개, 추정 API 요금 $0.000794808이다. 요청 지연 중앙값은 약 209.89ms다. 후속 원본은 `current-completion-v1.json`, `current-completion-live-v1.json`에 남겼고 첫 평가 집계 `summary-v1.json`은 변경하지 않았다.

원시 `*-live-*.json` 호출 기록은 로컬 보관하며 공개 PR에서 제외한다. Git에는 검토한 합성 입력 사례와 요약만 포함한다. 요약의 측정치는 역사적 기록이며 원시 자료가 공개되었다는 의미가 아니다.
