# 제품 구현·검증

제품 설계·구현·디버깅·리뷰·검증 시 관련 절을 읽는다. 보안 도구의 적용 조건과 실행 방법은 [보안 가이드](GUIDE_SECURITY.md)를 따른다.

## 구현 원칙

- Next.js 코드를 변경할 때 설치 버전의 `node_modules/next/dist/docs/`에서 관련 가이드를 확인한다. `next.config.mjs`의 `agentRules: false`는 개발 서버가 AGENTS.md에 상세 지침을 자동 추가하지 않도록 유지하는 설정이다. 관련 기준은 [공식 agentRules 문서](https://nextjs.org/docs/app/api-reference/config/next-config-js/agentRules)를 따른다.
- 제품 범위·우선순위·완료조건은 Master PRD의 최신 관련 절을 직접 확인한다. 이 가이드에 제품 요구사항의 복제본을 유지하지 않는다.
- 사주 계산은 결정적 코드로 수행하고 경계조건을 검증한다. LLM이 간지·역법 변환을 만들어내게 하지 않는다.
- 계산된 사실, 프로젝트의 창작적 대응 규칙, AI 설명을 데이터와 UI에서 구분한다. 이름 뜻·어원·한자는 출처를 확인한다.
- 스택·계산 정책은 Master PRD의 최신 확정 결정을 따른다. Meta API 접근·계산 구현의 실현 가능성과 미완료 검증은 별도 게이트로 확인하며, 이미 확정된 결정을 과거 로컬 메모로 되돌리지 않는다.
- Phase 1 완료 전 NPC 대량 생성, 관계 그래프, 게임 엔진 연동이나 복잡한 계정·저장 구조를 선행 구축하지 않는다.
- 해커톤 기여는 Master PRD의 행사 기간과 출처 기록 원칙을 따른다. 이번에 옮긴 Codex 도구 설정과 기존 노하우는 행사 중 새로 구현한 제품 코드로 설명하지 않는다.

## 검증과 완료 보고

- API 키·토큰·자격증명은 서버 환경에서만 사용하며 저장소·브라우저 번들·로그에 노출하지 않는다. 예시 환경 파일에는 자리표시자만 넣는다.
- 사주 계산에서 시간대와 날짜 경계를 명시한다. 서버 타임스탬프는 timezone-aware 값으로 다루고, 인증 정보를 localStorage에 저장하지 않는다. CORS는 실제 허용 출처와 자격증명 정책에 맞게 설정한다.
- 입력과 AI의 구조화 응답을 검증하고, 오류·로딩·빈 결과 상태를 처리한다.
- 검사 명령은 현재 package.json·README·CI 등 실제 프로젝트 정의에서 확인한다. 없는 backend/frontend/admin 명령을 가정하지 않으며, 명령 변경은 이 가이드나 관련 실행 문서에 반영한다.
- 변경에 맞는 최소 검증부터 실행한다. 제품 코드 변경은 관련 정적 검사·단위/통합 테스트·빌드로 확인하고, 문서·설정 변경은 구문·참조·일관성을 확인한다.
- 사주 계산의 절기·시간대·날짜 경계와 이름 데이터의 정확성을 우선 검증한다. 브라우저 실기능 확인은 사용자가 수행하며 Playwright E2E는 별도 요청 없이 도입하지 않는다.
- 실행하지 못한 검증은 이유와 함께 알린다. 성공한 검증은 새 변경·실패·미해결 우려 없이 반복하지 않는다.
- 모든 변경 후 [Master PRD 기록·동기화 절차](GUIDE_PRD_SYNC.md)를 적용한다. 의미 있는 구현은 원본의 완료조건, README와 해커톤 기여 기록도 확인한다. 사소한 수정마다 새 문서를 만들 필요는 없다.
