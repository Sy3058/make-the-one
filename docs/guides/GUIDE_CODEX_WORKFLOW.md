# Codex 작업 방식

계획·구현·디버깅·리뷰 또는 모델·위임·스킬·훅·Jev 관련 작업 전에 관련 절을 읽는다. 단순 문서 수정에는 전체 워크플로를 강제하지 않는다.

- 계획·설계에는 `$fable-plan`, 구현·디버깅에는 `$fable-exec`, 리뷰에는 `$fable-review`를 적용한다. 단순 수정에 계획·Council·별도 리뷰를 일괄 강제하지 않는다.
- 중요한 아키텍처나 출시 계획은 필요할 때 `$council-review`로 여러 관점을 검토한다.
- 기본 모델은 `gpt-6.1-sol`, reasoning은 `medium`이다. 계획·구현·디버깅·리뷰와 최종 검증을 메인 Sol이 직접 맡는다. 설정 파일의 변경을 실행 중 세션의 모델 전환으로 설명하지 않는다.
- 요구사항이 명확한 작은 수정은 Sol Low로 처리할 수 있다. 사주 계산 규칙·시간대·절기 경계, 보안 설계, 여러 모듈에 걸친 원인 조사처럼 판단이 복잡하면 Sol High를 우선 사용한다. High에서도 상충하는 근거·실패가 남으면 XHigh를 고려하며 Max를 기본화하지 않는다.
- Astra는 기본 계획자나 필수 리뷰어가 아니다. Sol에서 해결되지 않은 중요한 설계 문제 또는 독립적인 추가 검토가 필요한 경우 `gpt-6-astra` High/XHigh를 선택적으로 고려한다. 단순히 보안·아키텍처라는 이유만으로 모델을 올리지 않는다.
- 실행 환경과 상위 지침이 위임을 허용하는 경우에만 확정된 검색·반복 수정은 `gpt-6-luna` Low, 독립적인 일반 구현은 `gpt-6.1-sol` Low/Medium에 맡길 수 있다. 단일 짧은 조회는 직접 처리하고, 메인이 실제 diff와 검증을 확인한다. 위임을 필수 절차로 만들지 않는다.
- `gpt-6.1-terra`는 화면 중심 조사·시각적 비교가 실제로 필요한 경우의 선택지다. 일반 코딩의 기본 모델로 추가하지 않는다. 실제 전환·위임 도구와 모델이 제공될 때만 실행하며, 실행하지 않은 모델 전환이나 병렬 검토를 수행했다고 말하지 않는다.
- `$typesafe-ai`는 TypeSafe를 쓰는 작업에만 적용한다. 스킬 설치를 제품의 TypeSafe 도입이나 외부 API 호출 승인으로 간주하지 않는다.
- 사용자 요청으로 Jev 개발 보조 도구의 실제 시험 운영을 시작했다. 배정·관련성 판단이 필요한 작업에서 `scripts/jev_harness.py`를 추천 도구로 사용할 수 있으며 사용 기준·측정 기록은 `docs/JEV_TRIAL.md`를 따른다. Jev 결과가 실행 권한·자동 위임·원문 삭제를 허용하지 않는다. 제품 Meta 모델과는 별도다.
- 스킬·훅의 구성과 적용 한계는 `docs/CODEX_SETUP.md`를 참고한다.
